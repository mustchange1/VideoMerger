## 4. VM Automatic implementation audit

All spec features verified present in code (branch tip, post-repair):
watchdog watching (fallback: 1 s polling), 300 s reconciliation, immediate
startup scan, file stability (size/mtime + lock probe, 8 s default, 0.5–300 s
valid range), deterministic audio/script pairing + conflict warnings,
sequential queue (concurrency fixed at 1, validated), persistent job states
(NEW/WAITING_FOR_STABILITY/READY/QUEUED/RUNNING/SUCCEEDED/FAILED/
RETRY_PENDING/INTERRUPTED) with history, limited retries (3), crash recovery
(RUNNING → INTERRUPTED → retry), output validation (exists/non-zero/readable/
stable), event debounce, job-local seed (fresh per job, reused on retry,
reseeded on Retry+Randomize Again), job-local randomization (master order
untouched — verified by byte-compare test), logging (rotating file + GUI),
single-instance lock, opt-in Windows autostart (default OFF), GUI controls
(Start/Stop Watching, Scan Now, Pause/Resume, Retry, Retry+Randomize Again,
Open folders), defaults: watcher OFF, archive OFF, require_script strict.

DEFECT FOUND AND REPAIRED (20fdf6d): `SingleInstanceLock` (applock.py) was
never wired into `launch()` → single-instance protection was inert. Repair:
launch() acquires the lock, shows a message + exits 1 when already running,
releases on exit. Regression tests: tests/test_vm_automatic_applock.py (3).
